# UPSTREAM-MAP — ZCode v3.18.0 source map for additive Hop3 work

- **Imported baseline commit:** `b95ebaffeab641907b38652f45c1502bd762972d` (zai-org/ZCode `main`, v3.18.0, source sync 2026-11-11)
- **Verified:** every path below was verified against the imported tree with Glob/Grep/Read during the Stage 1 baseline import (2026-11-12). No path is guessed.
- **Purpose:** HOP3_RULES.md §3 requires that, before modifying any upstream capability, the owner, callers, compatibility contract, tests and existing behavior are identified. This map is that record. It is also the entry point for the Earn-surface port (STAGE-1.md D2–D6) into the real ZCode shell.
- **Notation:** paths are relative to the repository root. `shared` = `packages/shared`, etc.

- Owner package/path: `packages/ui` (shared shell) + `packages/web/src/main.tsx` (web) + `packages/desktop/src/main` and `packages/desktop/src/renderer` (Electron)

---

## Two most useful additive levers (from the audit above)

1. **New RPC service:** `createServiceDescriptor` + register in `createLocalServices` (`packages/services/src/node.ts`) — auto-exposed to renderer/web via `useServices()`.
2. **Composer/session commands:** v4 command envelopes (`packages/shared/src/zcode-protocol-v4`, `packages/ui/src/v4/commandFactory.ts`) for new conversation actions, plus `requestComposerTextInsert` for prefilled (never auto-sent) composer handoff.

Hop3 Earn work should hang off: a tab kind in `tabStore` (D5 UI), one service in `@zcode/services` for the domain (D2/D4), migrations in `tasksDatabase` for persistence, `McpSettingsSection`/adapters MCP path for Upwork/Fiverr connectors (D3), the cron scheduler for source freshness, and `requestComposerTextInsert` for the application-assistance handoff (D6).
